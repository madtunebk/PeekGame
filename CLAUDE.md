# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PeekGame runs unmodified Windows x64 games on Linux without Wine or Proton. It maps the game's EXE and the PE DLLs it ships (UnityPlayer, Mono, GameAssembly, DXVK…), runs their machine code directly, and binds their imports to Rust implementations of the Windows API that sit on X11, GLX, Vulkan, PulseAudio, OpenSSL and ICU. `--relink` instead turns an EXE into a native ELF that links the same runtime statically.

## Commands

```sh
cargo build --release --offline        # builds target/release/peekgame + libgame_imports.{so,a}
python3 tools/stage_dist.py            # copy runner, Windows DLLs (DXVK) and libs into dist/
./dist/peekgame GAME.exe --run [ARGS]  # execute; args after --run go to the game
./dist/peekgame --analyze GAME.exe     # static import report -> reports/<stem>/imports.{json,txt}
./dist/peekgame GAME.exe --relink [--strip] [--output DIR]  # native ELF (--strip: no symbols)
./dist/peekgame GAME.exe --package --output DIR

cargo test --offline                   # Rust unit tests
cargo test --offline <test_name>       # single Rust test
cargo clippy --offline --all-targets -- -D warnings
python3 tests/test_<name>.py           # single integration test
```

Run games with `dist/peekgame`, not `target/`. Re-run `stage_dist.py` after every release build you intend to run.

The build needs: X11, GL, fontconfig, OpenSSL (`libssl-dev`), ICU (`libicu-dev`) and `pkg-config`. `build.rs` compiles C helpers with `-Werror`:
- `native/steam_bridge/`
- the DirectWrite backend `src/api/text/dwrite/backend.c`
- the GLX backend, plus GL thunks generated by `tools/gen_gl_bridge.py` from the system `GL/glext.h`
- `src/host/x11/modes.c`

`tools/build_dxvk_x11.py` builds DXVK against the project's own X11 WSI, using the pinned sources in `sources/`. `tools/fetch_sources.py` restores those sources in a fresh checkout. Dependency revisions and checksums are tracked in `deps/`.

**Integration tests.** Each `tests/test_<name>.py` is one script of sequential asserts. It compiles a small C fixture `tests/<name>.c` with `x86_64-w64-mingw32-gcc`, usually `-nostdlib` with an entry point named `entry`. It then runs the result through `target/release/peekgame ... --run` and checks the exit code and output, so build in release first. Tests that open windows use a private Xvfb (`tests/private_x11.py`) and never the desktop. Many tests run the same fixture twice: once as a PE and once relinked as an ELF.

**Debug environment variables.** `PEEKGAME_TRACE_{CERTS,GL,INPUT,AUDIO,ERRORS,UNITY_INPUT,FILES,CRYPTO,HTTP,HTTP_BODY,SSPI,WINDOW}`, `PEEKGAME_TRACE_LAST_ERROR=<module>|all` (call sites that read a nonzero GetLastError/WSAGetLastError), `PEEKGAME_IMPORT_TRACE`, `PEEKGAME_X11_ERRORS`, `PEEKGAME_NO_XI2` (forces raw mouse deltas back onto the accelerated core X11 pointer instead of unaccelerated XInput2 raw motion), `PEEKGAME_TRACE_SOCKETS` (entry/exit of blocking Winsock calls — connect/send/recv/sendto/recvfrom/WSASend/WSARecv/select — with socket handle, host fd, thread id and result; a trailing `enter` with no matching `exit` is the call a hung thread is blocked in), `PEEKGAME_HTTP_OFFLINE` (fails every WinHTTP request with CANNOT_CONNECT, as if there were no network, so a game that gates menus on optional online services — e.g. DOOM Eternal's campaign Settings waiting on PlayFab — falls back to offline instead of hanging; any value but `0`/empty forces offline, `0` forces online, and unset defers to the per-game `Quirk::ForceHttpOffline` (not enabled for any game by default — opt in per game or via the env var; for DOOM Eternal it also sidesteps the Settings-menu PlayFab-Party text-to-speech hang and the ~2-min disconnect)). Vulkan presentation: `PEEKGAME_VULKAN_PRESENT=immediate|mailbox|fifo|relaxed` overrides the swapchain present mode, `PEEKGAME_VULKAN_FPS=N` caps presents, and `PEEKGAME_VULKAN_IMAGES=N` lowers the swapchain image count (floor 2). Unreal shipping builds (`*-Win64-Shipping.exe`) that ask for an uncapped IMMEDIATE/MAILBOX swapchain default to FIFO vsync with a 3-image queue (`quirks::prefers_vsync`), so the GPU paces to the refresh instead of running at 100%; `PEEKGAME_VULKAN_PRESENT`/`PEEKGAME_VULKAN_IMAGES` override it. FIFO's deep queue adds mouse latency but keeps the GPU paced at the refresh; `PEEKGAME_VULKAN_PRESENT=fifo PEEKGAME_VULKAN_IMAGES=2` gives that low GPU use with a short, low-latency queue. Mailbox has the lowest latency but renders flat out (100% GPU) unless the game's own frame limit is set. `PEEKGAME_WINDOWS_DLLS` defaults to `windows-dlls/` beside the binary and holds real Windows DLLs that override PeekGame's own (this is how DXVK's d3d11/dxgi are loaded).

## Architecture

- **`src/pe/`**: the one PE reader, shared by the analyzer, the runner and the relinker (headers, imports, delay imports, relocations, TLS).
- **`src/loader/` and `src/images/`**: the runner and program DLL loading.
  - Maps images at their preferred base or relocates them.
  - Binds imports by name, ordinal, forwarder or API set (`api-ms-win-*` resolves to kernel32).
  - Gives each DLL a static TLS slot and runs DllMain/TLS callbacks in dependency order.
  - Implements `LoadLibrary` search (EXE directory, then `SetDllDirectory`, then the current directory, case-insensitive).
  - DLLs that PeekGame implements always win over files on disk.
- **`src/registry/`**: the export catalog, the single source of truth for what is callable. Each subsystem file declares `exports! { export!(dll, name, category, status, scope, fn), ... }`. `implemented!` is shorthand for kernel32, and `data!` declares data exports.
  - Every entry also emits a global link symbol `peekgame.<dll>.<name>`, which is how relinked ELFs bind their IAT through the static linker.
  - `status` is `implemented` or `partial`, and `scope` must state what is actually supported.
  - System declarations are split under `src/registry/system/`.
- **`src/api/<subsystem>/`**: the implementations, all `extern "win64"`. Subsystems:
  - `system`, `threading`, `memory`, `filesystem`, `crt` (msvcrt + UCRT), `window` (USER32 on X11)
  - `graphics` (`vulkan.rs` is the `vulkan-1.dll` Win64-to-SysV thunk used by DXVK; there is also WGL over GLX)
  - `audio` (WASAPI over Pulse), `network` (Winsock, CRYPT32/OpenSSL, SSPI, WinHTTP), `com`, `shell`, `text` (DirectWrite), `steam`
- **`src/seh/`**: Windows x64 SEH. Covers `RaiseException`, unwinding through `.pdata` and runtime function tables, vectored handlers, and hardware faults translated from Linux signals.
- **`src/host/`**: Linux-side state.
  - TEB/PEB in `gs` (`teb.rs`) and Windows thread entry and templates
  - X11 display and windows (`x11/`), the GLX backend, the PulseAudio client, ICU-backed NLS (`nls/`), paths
- **Diagnostics.** `src/api/system/dynamic.rs` records every runtime `GetProcAddress`/`LoadLibrary` request to `logs/<stem>/dynamic-imports.tsv`. Rules:
  - An unimplemented static import becomes a trap that prints `STOP: missing Windows API DLL!Name` when called.
  - Unavailable dynamic lookups return Windows errors 126/127.
  - Static imports and dynamic lookups are evidence of what a game *may* call, not proof of execution.
- **Other modules:**
  - `src/relink/`, `relink.rs`, `relinked.rs`: ELF relinking
  - `src/package/`: packaged launchers
  - `src/analysis/` and `src/report/`: `--analyze`
  - `src/abi.rs`: Windows types and constants
  - `src/quirks/`: per-game behavior quirks (app-compat). The one place game-specific workarounds live, keyed by EXE stem (or an engine predicate). A hook point asks `quirks::active(Quirk::X)` instead of hard-coding a game name inline; the normal path runs for every game not listed. Each quirk's reason belongs in the engine ledger.

## Rules for API work

- **No fake success.** A missing API stops with a STOP trap, never a stub that returns success. Unsupported arguments return a real Windows error code (for example `ERROR_NOT_SUPPORTED`, or 50) or stop explicitly. Registry keys that nothing real backs are reported as missing. Unknown APIs are never auto-aliased.
- **DRM is never bypassed.** The Steam bridge forwards to the real `steamclient.so` and never answers on Steam's behalf.
- **Callbacks into Windows code** (WndProcs, hooks) run without registry locks or state borrows held. Linux objects (Display pointers, X11 IDs) are never handed to Windows code; HWND and similar handles are private tokens.
- **Register what you implement.** Adding an API means implementing it under `src/api/<subsystem>/` and registering it in the matching `src/registry/` file with an honest status and scope.
- **Document imports.** Every new or changed import gets an entry in its engine ledger, `docs/engines/<engine>-imports.md`, in the same change. Follow the template in `docs/import-tracking.md`: trigger, contract, implementation, scope, verification and impact on other engines. A game reaching its menu does not establish gameplay, audio, save or shutdown support.
- **Contract references.** API behavior references live in `docs/api-contracts.md`. Local Microsoft docs are at `../sdl3-window/win32/desktop-src/` (sibling checkout).
- **Keep games and logs out of Git.** `games/`, `logs/`, `reports/`, `dist/`, `relinked/`, `packages/`, `sources/` and `windows-dlls/` are gitignored. Proprietary game files, binaries and raw logs stay out of version control.
